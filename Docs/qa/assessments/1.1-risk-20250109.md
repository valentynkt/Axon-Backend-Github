## Critical Risks Requiring Immediate Attention

### 1. DATA-001: Partial Unique Index Implementation Failure

**Score: 9 (Critical)**
**Probability**: High - Complex constraint that's easy to misconfigure in EF Core
**Impact**: High - Could allow multiple verified owners for same wallet, breaking core security invariant
**Mitigation**:
- Verify generated SQL for partial unique index matches PostgreSQL syntax exactly
- Test with concurrent transactions attempting to create duplicate verified owners
- Add database-level constraint validation tests using Testcontainers
**Testing Focus**: Concurrent ownership creation, race condition testing, constraint violation handling

### 2. SEC-001: Wallet Ownership Hijacking Risk

**Score: 9 (Critical)**
**Probability**: High - Without proper constraint enforcement, ownership conflicts possible
**Impact**: High - User could lose control of wallet, major security breach
**Mitigation**:
- Implement partial unique index correctly
- Add application-level double-checking before ownership creation
- Implement comprehensive audit logging for ownership changes
**Testing Focus**: Security testing for ownership transfer scenarios, penetration testing on ownership endpoints

## Risk-Based Testing Strategy

### Priority 1: Critical Risk Tests
- **Concurrent Ownership Tests**: Multiple threads attempting to claim same wallet
- **Partial Unique Constraint Tests**: Verify only one verified & signing owner allowed
- **Security Penetration Tests**: Attempt wallet hijacking scenarios
- **Transaction Isolation Tests**: Ensure ACID properties maintained

### Priority 2: High Risk Tests
- **ETag Consistency Tests**: Verify fingerprint matches expected calculation
- **ULID Generation Tests**: Validate uniqueness and sort order
- **Concurrency Token Tests**: Test optimistic concurrency control
- **Performance Load Tests**: Measure query performance under load

### Priority 3: Medium/Low Risk Tests
- **Enum Mapping Tests**: Verify database values match domain enums
- **Migration Tests**: Test migration up/down scenarios
- **Index Performance Tests**: Validate query plans use indexes
- **Architecture Compliance Tests**: Verify no infrastructure leakage to domain

## Risk Acceptance Criteria

### Must Fix Before Production
- DATA-001: Partial unique index must be correctly implemented and tested
- SEC-001: Wallet ownership security must be bulletproof
- SEC-002: Concurrency control must be properly configured

### Can Deploy with Mitigation
- DATA-002: ETag issues can be monitored and fixed post-deployment
- TECH-001: ULID issues unlikely if using standard library
- PERF-001: N+1 queries can be optimized iteratively

### Accepted Risks

## Monitoring Requirements

Post-deployment monitoring for:
- **Constraint Violations**: Alert on any unique constraint violations
- **Ownership Changes**: Audit log all wallet ownership modifications
- **Query Performance**: Monitor ETag fingerprint query execution time
- **Error Rates**: Track migration and database connection errors
- **Concurrency Conflicts**: Monitor optimistic concurrency failures
