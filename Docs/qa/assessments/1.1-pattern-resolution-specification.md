# Story 1.1: Pattern Resolution Specification

## Executive Summary

**Issue**: Architectural inconsistency between BaseIdentityCommandEndpoint and BaseIdentityQueryEndpoint dependency injection patterns
**Impact**: CONCERNS quality gate blocking Epic 1 foundation
**Decision Required**: Choose consistent pattern across both base classes
**Timeline**: Must be resolved before Story 1.1 implementation begins

## Current State Analysis

### Chat Module Existing Patterns

**BaseChatCommandEndpoint Pattern**:
```csharp
public abstract class BaseChatCommandEndpoint<TRequest, TResponse, TCommand, TDomainResult>
    : BaseMappedEndpoint<TRequest, TResponse>
{
    protected BaseChatCommandEndpoint(ILogger logger) : base(logger) { }
    
    // Abstract method delegation - no MediatR injection
    protected abstract Task<Result<TDomainResult, Error>> ExecuteCommand(TCommand command, CancellationToken ct);
}
```

**BaseChatQueryEndpoint Pattern**:
```csharp
public abstract class BaseChatQueryEndpoint<TRequest, TResponse, TQuery, TDomainResult> 
    : BaseMappedEndpoint<TRequest, TResponse>
{
    private readonly IMediator _mediator;
    
    protected BaseChatQueryEndpoint(IMediator mediator, ILogger logger) : base(logger)
    {
        _mediator = mediator;
    }
    
    // Direct MediatR usage
    protected override async Task<Result<TResponse, Error>> ExecuteAsync(TRequest request, CancellationToken ct)
    {
        return await MapExecuteMap<TQuery, TDomainResult>(
            request,
            (query, cancellationToken) => _mediator.Send(query, cancellationToken),
            ct);
    }
}
```

### Problem Analysis

**Inconsistency Impact**:
1. **Developer Confusion**: Different patterns for Commands vs Queries
2. **Testing Complexity**: Different mocking strategies required
3. **Maintenance Burden**: Two different inheritance approaches to maintain
4. **Architectural Debt**: Mixed patterns make future changes harder

## Solution Options Analysis

### **Option 1: Abstract Method Consistency (RECOMMENDED)**

**Approach**: Standardize both base classes to use abstract method delegation

**BaseIdentityCommandEndpoint**:

### **Option 2: MediatR Injection Consistency** (Alternative)

**Approach**: Standardize both base classes to inject IMediator

**Pros**:
- Follows modern CQRS patterns with direct MediatR usage
- Reduces boilerplate in concrete implementations
- Consistent with some other base classes

**Cons**:
- Breaks compatibility with existing Chat Command pattern
- Requires changing Story 1.1 specification significantly
- More coupling to MediatR in base classes
- Chat module has mixed patterns (confusing precedent)

### **Option 3: Hybrid Approach** (Not Recommended)

**Approach**: Allow both patterns to coexist

**Why Not Recommended**:
- Perpetuates architectural inconsistency
- Increases cognitive load for developers
- Makes testing strategies inconsistent
- Doesn't resolve the original CONCERNS gate issue

## Decision Matrix

| Criteria | Option 1 (Abstract) | Option 2 (MediatR) | Option 3 (Hybrid) |
|----------|-------------------|-------------------|-------------------|
| **Consistency** | ✅ High | ✅ High | ❌ Low |
| **Chat Module Alignment** | ✅ Perfect Command | ⚠️ Query only | ❌ Mixed |
| **Developer Experience** | ✅ Consistent | ✅ Consistent | ❌ Confusing |
| **Story 1.1 Impact** | ✅ Minimal | ⚠️ Specification change | ✅ None |
| **Testing Strategy** | ✅ Consistent mocking | ✅ Consistent mocking | ❌ Mixed strategies |
| **Future Flexibility** | ✅ High | ⚠️ MediatR coupled | ❌ Technical debt |
| **Implementation Time** | ✅ 1 day | ⚠️ 2 days | ❌ Ongoing confusion |

## Recommended Solution: Option 1

### **Rationale**:

1. **Minimal Story Impact**: Story 1.1 already specifies abstract method approach
2. **Perfect Chat Command Alignment**: Maintains exact inheritance pattern
3. **Consistent Developer Experience**: Same pattern for both Command and Query
4. **Testing Simplicity**: Single mocking strategy across all base classes
5. **Future Flexibility**: Concrete implementations can choose their own dependencies

### **Implementation Changes Required**:

**Story 1.1 Specification Updates** (Minor):
- Update BaseIdentityQueryEndpoint to use abstract method instead of IMediator injection
- Remove type constraint requiring BasePagedRequest (Identity endpoints don't need pagination)
- Add consistent abstract method signatures

**Concrete Endpoint Impact**:
- GetCurrentUserEndpoint: Inject IMediator in constructor, use in ExecuteQuery method
- ExchangeTokenEndpoint: Inject required services, use in ExecuteCommand method
- ProcessDynamicWebhookEndpoint: Inject required services, use in ExecuteCommand method
