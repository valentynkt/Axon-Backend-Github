### Data Models
**AxonUserId Strong ID** [Source: Epic 4a implementation + architecture/71-smart-caching-architecture-epic-4.md]
- **Type**: `StronglyTypedId` struct from BuildingBlocks
- **Purpose**: Type-safe user identity throughout the system
- **Caching**: Will be cached with progressive hierarchy (Request → Memory → Database)

**Caching Strategy** [Source: architecture/71-smart-caching-architecture-epic-4.md#cache-key-patterns--ttl-strategy]
- **Cache Key Pattern**: `axon:user:{dynamicUserId}`
- **TTL**: 15 minutes sliding, 30 minutes absolute
- **Priority**: High (prevents eviction under memory pressure)
- **Performance Target**: <1ms for cached lookups

### API Specifications
**Interface Enhancement Pattern** [Source: architecture/71-smart-caching-architecture-epic-4.md#httpcontextuserservice-epic-4-brutal-refactoring]
```csharp
// NEW Epic 4b methods - ADDITIVE ONLY
/// <summary>
/// Gets the current authenticated user's internal AxonUserId with smart caching.
/// Progressive cache hierarchy: HttpContext.Items (0ms) → IMemoryCache (1ms) → Database (20-50ms)
/// </summary>
Task<AxonUserId?> GetAxonUserIdAsync(CancellationToken ct = default);

/// <summary>
/// Attempts to get AxonUserId from cache only (no database fallback).
/// Used for sync contexts where database queries are not acceptable.
/// </summary>
bool TryGetAxonUserId(out AxonUserId axonUserId);
```
