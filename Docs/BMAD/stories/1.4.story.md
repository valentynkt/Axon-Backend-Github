# Story 1.4: `/auth/exchange` Command Handler (Create/Resolve & Link)

## Status
**Ready for Done**

## Story
**As an** application engineer,  
**I want** a command that validates, normalizes, batch-ensures wallets, links **verified & signing** ownerships, applies defaults, and persists atomically,  
**so that** `exchange` is safe to retry and enforces invariants.

## Acceptance Criteria
1. **Single Transaction**: `ExchangeCredentialCommand` implements sequence with a **single transaction**
2. **Batch Operations**: Batch `EnsureManyByChainAndAddressAsync` prevents N+1; optional `TouchLastSeenAsync` does not affect ETag
3. **Stable Response**: Returns `ExchangeDynamicTokenResponse` with stable counts
4. **Conflict Handling**: **409** on conflicting verified owner; `ApiError { code, message, details:{ chainId,address } }`; never exposes other principal id

## Integration Verification
- IV1: Endpoint isolated under `/auth` and does not impact other APIs
- IV2: 409 path validated via partial-unique index in integration tests
- IV3: p50/p95 within acceptable dev/test bounds

### Technical Details from Architecture

**Repository Contracts** [Source: architecture.md#application-layer]:
```csharp
// Read-side credential resolution for command
Task<AxonPrincipal?> FindByCredentialAsync(
    ProviderType providerType, string issuer, string subject, CancellationToken ct = default);

// Batch wallet ensure to reduce round-trips
Task<IReadOnlyDictionary<(string chainId, Address address), WalletId>>
  EnsureManyByChainAndAddressAsync(IEnumerable<(string chainId, Address address)> items, CancellationToken ct = default);

// Optional: bump last-seen in batch (should not affect ETag)
Task<int> TouchLastSeenAsync(IEnumerable<WalletId> ids, DateTimeOffset seenAt, CancellationToken ct = default);
```

**Domain Invariants** [Source: architecture.md#domain-model]:
- **Global wallet uniqueness** by `(chainId, address)`
- **Single verified & signing owner** per wallet (partial-unique index enforcement)
- **No silent reassignments** - conflicts return 409 with privacy-safe details
- **Verified-first defaults** - chain default must reference verified & signing wallet
- **Idempotent exchange** - replays produce stable state and counts

**Error Handling Strategy** [Source: architecture.md#error-handling-strategy]:
- Result pattern for domain workflows returning `Result<Success, Error>`
- HTTP mapping: Validation/auth → 400/401, Invariant violations → 409, Business rules → 422, Rate limit → 429
- Privacy for 409: Response MUST NOT include principal identifiers other than caller's
- Use `ApiError.details = { chainId, address }` only for conflicts

**Performance Requirements** [Source: architecture.md#database-schema]:
- Single transaction for atomicity across Principal creation, wallet ensuring, ownership linking, and defaults
- Batch operations prevent N+1 queries during wallet processing
- Compiled queries for hot paths
