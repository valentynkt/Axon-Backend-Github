### Technical Details from Architecture

**Rate Limiting Configuration** [Source: architecture/12-rate-limiting-epic-2-production-implementation.md]:
- **Policy**: `/auth/exchange` limited to **10 requests/minute per IP address** using fixed window
- **Implementation**: ASP.NET Core rate limiting with IP-based partitioning
- **Headers**: Standard rate limiting headers (`X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`)
- **429 Response**: Must include `Retry-After` header with seconds until reset

**Middleware Configuration** [Source: architecture/12-rate-limiting-epic-2-production-implementation.md]:
```csharp
// Rate limiting services configuration
builder.Services.AddRateLimiter(options =>
{
    options.RejectionStatusCode = 429;
    options.GlobalLimiter = PartitionedRateLimiter.Create<HttpContext, IPAddress>(context =>
    {
        var ipAddress = context.Connection.RemoteIpAddress;
        
        if (context.Request.Path.StartsWithSegments("/auth/exchange"))
        {
            return RateLimitPartition.GetFixedWindowLimiter(
                ipAddress,
                _ => new FixedWindowRateLimiterOptions
                {
                    PermitLimit = 10,
                    Window = TimeSpan.FromMinutes(1),
                    QueueProcessingOrder = QueueProcessingOrder.OldestFirst,
                    QueueLimit = 0
                });
        }
        
        return RateLimitPartition.GetNoLimiter(ipAddress);
    });
});
```

**HTTP Response Headers** [Source: architecture/12-rate-limiting-epic-2-production-implementation.md]:
- **Success Responses (200 OK)**: `X-RateLimit-Limit: 10`, `X-RateLimit-Remaining: 7`, `X-RateLimit-Reset: 1694123456`
- **Rate Limited Responses (429)**: `Retry-After: 45`, `X-RateLimit-Limit: 10`, `X-RateLimit-Remaining: 0`, `X-RateLimit-Reset: 1694123456`

### Technical Constraints

**ASP.NET Core Rate Limiting** [Source: architecture/3-tech-stack-final.md]:
- Must use ASP.NET Core built-in rate limiting middleware (available in .NET 10)
- IP address extraction from `HttpContext.Connection.RemoteIpAddress`
- Fixed window algorithm for consistent behavior and simple implementation
- No queueing (`QueueLimit = 0`) for immediate rejection when limit exceeded

**Error Handling Integration** [Source: architecture/11-error-handling-strategy.md]:
- 429 responses must follow existing `ApiError` envelope format
- Rate limit errors should use existing `Error.RateLimit()` factory method
- Proper HTTP status mapping through `ErrorHttpMapping.cs`
- Maintain consistency with other endpoint error responses

**Performance Requirements** [Source: architecture/12-rate-limiting-epic-2-production-implementation.md]:
- Rate limit checks must add < 1ms overhead to request processing
- Memory efficient IP address tracking with automatic cleanup
- Integration with existing OpenTelemetry tracing without performance impact
- Minimal impact on non-rate-limited endpoints
