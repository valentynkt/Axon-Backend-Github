## Architecture Decision: Dependency Injection Pattern Consistency

**Decision**: Both BaseIdentityCommandEndpoint and BaseIdentityQueryEndpoint will use abstract method delegation (no MediatR injection in base classes)

**Rationale**: 
- Aligns with existing Chat Command pattern for consistency
- Provides uniform developer experience across Command/Query endpoints  
- Enables flexible dependency injection in concrete implementations
- Maintains clean separation between base infrastructure and business logic

**Implementation Pattern**:
```csharp
// BOTH base classes follow this pattern
protected BaseIdentityCommandEndpoint(ILogger logger) : base(logger) { }
protected BaseIdentityQueryEndpoint(ILogger logger) : base(logger) { }

// Abstract method delegation (no MediatR in base classes)
protected abstract Task<Result<TDomainResult, Error>> ExecuteCommand(TCommand command, CancellationToken ct);
protected abstract Task<Result<TDomainResult, Error>> ExecuteQuery(TQuery query, CancellationToken ct);
```

**Concrete Implementation Strategy**:
```csharp
// Concrete endpoints inject their own dependencies
public GetCurrentUserEndpoint(IMediator mediator, ILogger<GetCurrentUserEndpoint> logger) : base(logger)
{
    _mediator = mediator;
}

protected override async Task<Result<CurrentUserResult, Error>> ExecuteQuery(GetCurrentUserQuery query, CancellationToken ct)
{
    return await _mediator.Send(query, ct);
}
```

## Dev Notes

### Architecture Context
[Source: docs/architecture/source-tree.md#source-code-structure, docs/architecture/coding-standards.md#architecture-patterns]

**Module Structure:** This story creates foundational infrastructure for the Identity module following Axon's established patterns:
- **API Layer Location**: `src/Api/Modules/` for shared base endpoint classes
- **Inheritance Pattern**: Base classes inherit from existing `BaseMappedEndpoint<TRequest, TResponse>`
- **CQRS Integration**: MapExecuteMap pattern connects HTTP layer to MediatR commands/queries

**Clean Architecture Compliance:** 
- API layer provides HTTP concerns only (routing, serialization, status codes)
- Business logic delegation through abstract ExecuteCommand/ExecuteQuery methods
- Domain results mapping handled by inherited MapExecuteMap functionality

### FastEndpoints Integration
[Source: docs/architecture/tech-stack.md#core-framework]

**FastEndpoints Configuration Requirements:**
- Use `Post(GetRoute())` and `Get(GetRoute())` for HTTP verb configuration  
- `AllowAnonymous()` for S1 stage (TODO markers for S2 Bearer auth)
- `Tags("Authentication")` for OpenAPI grouping
- `Consumes("application/json")` and `Produces("application/json")` declarations
- Standard HTTP status codes: 200, 400, 401, 403, 422, 500 with ProblemDetails

### CQRS Pattern Integration  
[Source: docs/architecture/coding-standards.md#cqrs-implementation]

**MapExecuteMap Pattern:** Both base classes must implement the established pattern:
1. Map HTTP request to command/query object
2. Execute command/query via abstract method (delegates to MediatR)
3. Map domain result back to HTTP response
4. Return `Result<TResponse, Error>` for consistent error handling

### File Locations and Naming
[Source: docs/architecture/source-tree.md#key-file-locations]

**Required File Paths:**
- `src/Api/Modules/BaseIdentityCommandEndpoint.cs`
- `src/Api/Modules/BaseIdentityQueryEndpoint.cs`

**Naming Conventions:**
- Generic type parameters: `TRequest, TResponse, TCommand/TQuery, TDomainResult`
- Abstract methods: `GetRoute(), GetSummary(), GetDescription(), GetSuccessResponse()`
- Execution methods: `ExecuteCommand(), ExecuteQuery()`
