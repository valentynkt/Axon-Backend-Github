# Story 1.2: Implement Exchange Token API Contract

## Status
Draft

## Story
**As a** frontend developer integrating Dynamic.xyz authentication,  
**I want** to exchange Dynamic.xyz JWT tokens for Axon user context via a REST API,  
**so that** I can authenticate users and retrieve their local wallet information for the application.

## Acceptance Criteria

1. Create `ExchangeTokenEndpoint` at `POST /api/v1/auth/exchange` inheriting from `BaseIdentityCommandEndpoint`
2. Create `ExchangeTokenRequestDto` with `ForceRefresh` boolean property (JWT comes from Authorization header)
3. Create `ExchangeTokenResponseDto` with user context and wallet information using primitive types only
4. Create `WalletDto` for wallet representation with primitive types (string IDs, not Strong IDs)
5. Create `ExchangeTokenRequestValidator` inheriting from `BaseValidator<T>` with minimal validation
6. Implement JWT extraction from `Authorization: Bearer <token>` header with proper validation
7. Return stub/mock response data for S1 stage (no Dynamic.xyz API integration yet)
8. Include proper OpenAPI documentation with example requests/responses
9. Configure endpoint with FastEndpoints patterns (route, tags, consumes/produces)
10. All code compiles with no warnings and follows Axon coding standards
11. **CRITICAL SECURITY**: Document S2 JWT signature validation requirements (Risk SEC-001 - Score 9)
12. **HIGH RISK**: Plan rate limiting implementation for authentication endpoint (Risk SEC-002 - Score 6)
13. **HIGH RISK**: Implement secure error handling without information disclosure (Risk SEC-003 - Score 6)
14. **HIGH RISK**: Plan JWT validation caching strategy (Risk PERF-001 - Score 6)

### API Contract Specifications
[Source: FRD S1 - API Contracts, Section 4.1 Exchange Token Endpoint]

**Endpoint Configuration:**
- **Route**: `POST /api/v1/auth/exchange`
- **Authentication**: JWT from `Authorization: Bearer <token>` header
- **Request Body**: `ExchangeTokenRequestDto` with optional `ForceRefresh` flag
- **Response**: User context with locally-mirrored wallet data

**JWT Header Processing:**
- Extract JWT from `Authorization: Bearer <token>` header
- Validate header format and JWT structure (3 segments)
- S1 Stage: Basic format validation only (no signature verification)
- S2 Stage: Full JWKS validation (marked with TODO comments)

### Data Model Specifications
[Source: FRD S1 - API Contracts, Section 4.1.3 Response DTO, Section 4.1.4 Wallet DTO]

**ExchangeTokenResponseDto Properties:**
- `UserId` (string) - Axon internal user identifier
- `DynamicUserId` (Guid) - Dynamic.xyz user identifier  
- `Email` (string) - User's verified email address
- `DisplayName` (string?) - User's display name (optional)
- `Username` (string?) - User's username (optional)
- `Wallets` (IReadOnlyList<WalletDto>) - Connected wallets
- `SyncedAt` (DateTime) - Last synchronization timestamp
- `SyncStatus` (string) - Current synchronization status

**WalletDto Properties:**
- `Id` (string) - Axon internal wallet identifier
- `DynamicWalletId` (Guid) - Dynamic.xyz wallet identifier
- `Address` (string) - Wallet public address/key
- `Chain` (string) - Blockchain type (SOL, ETH, etc.)
- `Provider` (string) - Wallet provider (phantom, metamask, etc.)
- `WalletName` (string?) - User-assigned name (optional)
- `LastSelectedAt` (DateTime?) - Last selection timestamp
- `ConnectedAt` (DateTime?) - Connection timestamp
