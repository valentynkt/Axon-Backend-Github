## Story

6. Ensure all DTOs use primitive types only (string, Guid, DateTime, bool, collections)

### Primitive Types Strategy
[Source: FRD S1 Section 2.1, Section 7.3]

**S1 Stage Requirements:**
- API contracts use only primitive types (string, Guid, int, DateTime, bool)
- No Strong ID dependencies (`UserId`, `WalletId`) in API layer
- Strong ID mapping happens in Application layer (S3+)
- Collections use `IReadOnlyList<T>`, `IReadOnlyDictionary<string, object>`

**Type Mapping Pattern:**
- Axon IDs: `string` (e.g., "usr_2Z4e8K9mNp3QrS7T", "wlt_8X2nMk9P4qR5sT7U")
- Dynamic.xyz IDs: `Guid` (e.g., Guid.Parse("95b11417-f18f-457f-8804-68e361f9164f"))
- Timestamps: `DateTime` with UTC handling
- Metadata: `IReadOnlyDictionary<string, object>` for JSON flexibility

### FluentValidation Configuration
[Source: docs/architecture/tech-stack.md#core-framework, existing BaseValidator pattern]

**BaseValidator Integration:**
- All validators inherit from `BaseValidator<T>` (already exists in Axon)
- Configure cascade mode: `CascadeMode.Stop` to prevent multiple error messages
- Use `RuleFor()` with `.WithMessage()` for custom error messages
- Add `Must()` custom validators for complex business rules

**Common Validation Patterns:**
- Required fields: `.NotEmpty().WithMessage("Field is required")`
- String length: `.MaximumLength(100).WithMessage("Must not exceed 100 characters")`
- Email format: `.EmailAddress().WithMessage("Invalid email format")`
- DateTime ranges: `.LessThanOrEqualTo(() => DateTime.UtcNow)`

### JSON Serialization Standards
[Source: docs/architecture/tech-stack.md#json--serialization]

**System.Text.Json Configuration:**
- Use camelCase naming policy for API responses
- Configure DateTime serialization as ISO 8601 UTC
- Handle `Dictionary<string, object>` for metadata properties
- Add `JsonPropertyName` attributes only when property name differs from JSON key
