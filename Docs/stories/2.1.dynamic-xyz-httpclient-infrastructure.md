# Story 2.1: Dynamic.xyz HttpClient Infrastructure

## Status
Draft

## Story
**As a** backend developer implementing Dynamic.xyz integration,  
**I want** robust HTTP client infrastructure with Polly resilience policies for Dynamic.xyz API calls,  
**so that** the system can handle network failures gracefully and provide reliable external service integration.

## Acceptance Criteria

1. Create `DynamicXyzOptions`, `JwtValidationOptions`, and `HttpClientOptions` configuration classes with IOptions pattern
2. Implement `IDynamicApiClient` interface and `DynamicApiClient` implementation using HttpClient factory
3. Configure HttpClient with Polly resilience policies: retry (3 attempts, exponential backoff), circuit breaker, and rate limiting
4. Create `ServiceCollectionExtensions` for Dynamic.xyz infrastructure registration in Identity module
5. Implement comprehensive error mapping from HTTP responses to Axon `Result<T, Error>` pattern
6. Configure separate JWKS HttpClient for JWT validation without authentication headers
7. Register all HTTP clients using IHttpClientFactory with proper configuration and timeouts
8. Add appsettings.json configuration section for all Dynamic.xyz options
9. Implement memory cache registration for JWKS caching strategy
10. Build passes with no warnings and all configurations follow IOptions pattern

**HTTP Client Requirements:**
- Two separate HttpClient instances: authenticated API client and JWKS client
- Main client: Bearer token, 30-second timeout, base URL configuration
- JWKS client: No authentication, 10-second timeout, for public key retrieval
- All clients must use IHttpClientFactory pattern with DI registration

### Polly Resilience Specifications
[Source: FRD S2 Section 4.1, HttpClient Configuration]

**Required Policies:**
1. **Retry Policy**: 3 attempts, exponential backoff (2^retry seconds), handles transient errors + 429
2. **Circuit Breaker**: 5 consecutive failures, 30-second timeout, automatic recovery
3. **Rate Limiting**: 500 requests/minute with burst allowance (50 requests)
4. **Timeout Policy**: Per-request timeouts (30s main, 10s JWKS)

**Error Handling Pattern:**
```csharp
// HTTP Status → Axon Error Type Mapping
HttpStatusCode.Unauthorized → Error.Unauthorized("Invalid API token")
HttpStatusCode.Forbidden → Error.Forbidden("Access denied") 
HttpStatusCode.NotFound → Error.NotFound("Resource not found")
HttpStatusCode.BadRequest → Error.Validation("Bad request")
HttpStatusCode.TooManyRequests → Error.RateLimit("Rate limit exceeded")
HttpStatusCode.RequestTimeout → Error.Timeout("Request timeout")
HttpStatusCode.ServiceUnavailable → Error.Unavailable("Service unavailable")
_ → Error.External($"API error: {response.StatusCode}")
```
