# Axon Backend - Product Requirements Document

## Project Overview
Axon Backend is a sophisticated Modular Monolith application built on .NET 10 preview, following Clean Architecture, Domain-Driven Design (DDD), and CQRS patterns. The system is designed for high scalability, maintainability, and clear separation of concerns.

## Architecture & Design Patterns

### Core Architectural Principles
- **Modular Monolith**: Self-contained modules with clear boundaries
- **Clean Architecture**: Domain → Application → Infrastructure → API layer separation
- **Domain-Driven Design (DDD)**: Rich domain models, aggregates, entities, value objects
- **CQRS Pattern**: Command Query Responsibility Segregation using MediatR
- **Result Pattern**: Functional error handling with Result<T> and Validation<T>
- **Strong Typing**: Type-safe identifiers using StrongId<T> pattern
- **Functional Programming**: Immutable records, Result/Option monads

### Technology Stack
- **.NET 10.0** (preview 5.25277.114) - Latest C# features
- **FastEndpoints** - High-performance minimal API framework
- **MediatR** - CQRS implementation and command/query dispatch
- **FluentValidation** - Request validation pipeline
- **Entity Framework Core 9.0** - ORM with PostgreSQL support
- **System.Text.Json** - High-performance JSON serialization
- **OpenTelemetry** - Observability and distributed tracing
- **xUnit** - Testing framework
- **FluentAssertions** - Readable test assertions
- **Testcontainers** - Integration testing with real databases
- **NSubstitute** - Mocking framework

## Core Features & Requirements

### 1. Domain Modeling
- **Rich Domain Models**: Business logic encapsulated in domain entities
- **Aggregates**: Consistency boundaries with invariant protection
- **Value Objects**: Immutable types for domain concepts
- **Domain Events**: Event-driven architecture support
- **Strong IDs**: Type-safe identifiers (UserId, OrderId, etc.)

### 2. CQRS Implementation
- **Commands**: State-changing operations with validation
- **Queries**: Read operations with pagination support
- **Handlers**: Isolated business logic processing
- **Pipeline Behaviors**: Cross-cutting concerns (validation, logging, idempotency)

### 3. Error Handling
- **Result Pattern**: Explicit error handling without exceptions
- **Validation**: Input validation with detailed error messages
- **Problem Details**: RFC 7807 compliant error responses
- **Domain Errors**: Business rule violations as first-class citizens

### 4. API Design
- **FastEndpoints**: Performance-optimized minimal APIs
- **Request/Response DTOs**: Clear contract definitions
- **Versioning**: API version management strategy
- **OpenAPI/Swagger**: Auto-generated documentation

### 5. Persistence Layer
- **Entity Framework Core 9**: Code-first approach
- **PostgreSQL**: Primary database
- **Migrations**: Database schema versioning
- **Repositories**: Abstraction over data access
- **Unit of Work**: Transaction management

### 6. Observability
- **OpenTelemetry**: Distributed tracing
- **Structured Logging**: Contextual logging with Serilog
- **Metrics**: Performance and business metrics
- **Health Checks**: Liveness and readiness probes

### 7. Testing Strategy
- **Unit Tests**: Domain logic validation
- **Integration Tests**: API endpoint testing
- **Testcontainers**: Real database testing
- **Test Data Builders**: Maintainable test fixtures

## Development Guidelines

### Code Standards
- **File-scoped namespaces**: Modern C# syntax
- **Records for DTOs**: Immutable data transfer objects
- **Target-typed new**: Simplified object creation
- **Nullable reference types**: Explicit null handling
- **Primary constructors**: Streamlined class definitions

### Patterns to Follow
1. **Result Pattern Usage**
   - All domain operations return Result<T>
   - No exceptions for expected failures
   - Clear error propagation

2. **Strong ID Pattern**
   - All entity IDs use StrongId<T>
   - Type safety at compile time
   - Prevents ID mix-ups

3. **Clean Architecture Layers**
   - Domain has no dependencies
   - Application depends only on Domain
   - Infrastructure implements Application interfaces
   - API orchestrates and configures all layers

4. **Module Boundaries**
   - No shared kernel between modules
   - Clear public contracts
   - Internal implementation details hidden

### Build Configuration
- **Warnings as Errors**: Enabled in Release mode
- **AOT Analysis**: Library compatibility verification
- **Deterministic Builds**: Reproducible outputs
- **XML Documentation**: Auto-generated for all public APIs
